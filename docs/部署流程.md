## 1. Cloudflare Workers 部署

Cloudflare Workers 是本博客的**原生主推平台**，具备全球边缘无服务器计算能力、极低延迟与零冷启动优势。本项目提供了一键式 **GitHub Actions 自动化 CI/CD 工作流**，所有敏感凭证保存在 GitHub 仓库中，无需在本地安装复杂环境。

### <a id="cloudflare-部署方法"></a>1.1 部署方法

#### 第一步：准备 Cloudflare 账户凭证
1. 登录 [Cloudflare 控制台](https://dash.cloudflare.com/)。
2. **获取 Account ID**：
   - 点击左侧菜单 **Workers & Pages** -> **Overview**，在右侧面板复制你的 **Account ID**。
3. **创建 API Token**：
   - 点击右上角头像 -> **My Profile** -> **API Tokens**。
   - 点击 **Create Token**，选择 **Edit Cloudflare Workers** 模板。
   - 权限确认包含 `Account - Workers KV Storage - Edit`、`Account - Workers Scripts - Edit`、`Account - D1 - Edit` 等，创建并复制该 Token。

#### 第二步：在 GitHub 仓库中配置 Secrets 与 Variables
进入你的博客 GitHub 仓库，导航至 **Settings** -> **Secrets and variables** -> **Actions**：
1. 在 **Repository secrets** 中添加敏感密钥（如 `CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID` 等）。
2. 在 **Repository variables** 中添加公开配置变量（如 `BLOG_URL`、`WORKER_NAME` 等）。

#### 第三步：手动触发部署
1. 进入 GitHub 仓库的 **Actions** 标签页。
2. 在左侧工作流列表中点击 **Deploy to Cloudflare Workers**。
3. 点击右侧 **Run workflow** 下拉按钮：
   - 分支选择 `main`。
   - 可在 `database_type` 下拉选项中自由选择：
     - `auto`（推荐）：自动检测（配置了 D1 或 Supabase 时自动连接，未配置时自动以纯净零数据库模式运行）。
     - `d1`：强制指定使用 Cloudflare D1 数据库。
     - `supabase`：强制指定使用 Supabase 数据库（部署脚本会自动清理 wrangler 的 D1 绑定，防止冲突报错）。
     - `none`：强制不使用任何数据库（彻底关闭阅读统计功能）。
4. 点击绿色 **Run workflow** 按钮启动，约 1~2 分钟即可完成全球发布！

### <a id="cloudflare-可选环境变量与配置"></a>1.3 可选环境变量与配置

#### 1. 缓存与数据库选型（可选功能）
博客支持通过 `unstorage` 统一键值抽象层接入缓存，并支持灵活的双数据库架构。**如果未配置任何数据库，系统将自动以零数据库超轻量模式运行，不报错、不发上报请求**。

| 配置项 | 类型 | 说明 |
| :--- | :---: | :--- |
| `CLOUDFLARE_KV_ID` | Secret / Variable | Cloudflare KV 命名空间 ID（用于边缘持久化缓存文章与清单；未配置时系统平稳降级为内存缓存） |
| `DATABASE_TYPE` | Variable | 默认数据库类型（可选 `auto`、`d1`、`supabase`、`none`，默认 `auto`） |
| `CLOUDFLARE_D1_ID` | Secret / Variable | Cloudflare D1 数据库 ID（若选用 D1 记录阅读量时配置） |
| `SUPABASE_URL` | Secret / Variable | Supabase 项目 URL（如 `https://xxxx.supabase.co`，若选用 Supabase 时配置） |
| `SUPABASE_KEY` | Secret | Supabase API Key（推荐填入受 RLS 保护的 `anon` 公开密钥） |
| `DATABASE_URL` / `SUPABASE_DB_URL` | Secret | Supabase PostgreSQL 直连串。**配置后 GitHub Actions 首次运行将自动建表与自增存储过程** |
| `SUPABASE_ACCESS_TOKEN` | Secret | Supabase 个人访问令牌（Management API Token，配置后亦可支持 Action 首次全自动建表） |

| 配置项 | 类型 | 示例值 | 说明 |
| :--- | :---: | :--- | :--- |
| `WORKER_NAME` | Variable | `my-blog` | Cloudflare Worker 实例名称（默认为 `blog`） |
| `GH_OWNER` | Variable | `your-username` | 存储文章的 GitHub 用户名（未配置时默认读取当前仓库拥有者） |
| `GH_REPO` | Variable | `blog` | 存储文章的 GitHub 仓库名（未配置时默认读取当前仓库名） |
| `GH_TOKEN` | Secret | `ghp_...` | GitHub 访问令牌（**仅在文章仓库为私有 Private 仓库时才需要配置**；公开仓库留空即可） |
| `PAT_TOKEN` | Secret | `ghp_...` | GitHub Actions CI/CD 令牌（仅用于同步模板等自动化工作流，不会部署到生产环境） |
| `PURGE_SECRET` | Secret | `your-secure-secret` | 缓存热刷新秘钥。文章推送触发 `sync-posts.yml` 时用于向博客发起 Webhook 自动预热 |

## 2. Vercel 部署

本项目支持通过 Vercel 原生 **Hono Zero-Config Preset (Fluid Compute)** 进行极速无服务器渲染（基于 [`src/index.ts`](../src/index.ts) 与 [`vercel.json`](../vercel.json)）。

### <a id="vercel-部署方法"></a>2.1 部署方法

本项目提供了 **GitHub Actions 自动化全流程部署（方案 A，强烈推荐）** 与 **Vercel 控制台手动关联导入（方案 B）** 两种方式。

#### 方案 A（推荐）：GitHub Actions 自动化一键部署（免手动配置面板）

通过本仓库内置的 [`.github/workflows/deploy-vercel.yml`](../.github/workflows/deploy-vercel.yml) 工作流，**你无需手动到 Vercel 网页控制台逐个添加环境变量**。脚本会自动识别项目、将 GitHub 中的环境变量批量同步至 Vercel，并以 Hono 原生运行时完成发布：

1. **获取 Vercel API Token**：
   - 登录 [Vercel 控制台](https://vercel.com/)。
   - 点击左下角头像 -> 弹出框最上方的设置按钮 -> **Settings** -> **Tokens**。
   - 点击 **Create** 创建一个新 Token（Scope 保持默认），复制生成的密钥。
2. **在 GitHub 仓库添加 Secret**：
   - 进入你的 GitHub 博客仓库，导航至 **Settings** -> **Secrets and variables** -> **Actions**。
   - 点击 **New repository secret**：
     - **Name**：`VERCEL_TOKEN`（或 `VERCEL_API_KEY`）。
     - **Value**：粘贴刚刚复制的 Token。
   - *(可选)* 若部署在团队 Team 账户下，可在 Variables 中添加 `VERCEL_ORG_ID`；若需自定义项目名可配置 `VERCEL_PROJECT_NAME`（默认自动采用仓库名称）。
3. **手动触发部署**：
   - 进入 GitHub 仓库的 **Actions** 标签页，在左侧选择 **Deploy to Vercel**。
   - 点击右侧 **Run workflow** 按钮即可一键完成全自动构建与发布（不占用 push 触发，按需手动运行）。

---

#### 方案 B：Vercel 控制台手动关联部署

如果你更习惯使用网页控制台操作：

1. **推送代码至 GitHub**：确保本仓库代码已推送到你的 GitHub 账户下。
2. **导入项目**：
   - 打开 [Vercel 控制台](https://vercel.com/)，点击 **Add New...** -> **Project**。
   - 找到并导入你的博客仓库。
3. **构建设置**：
   - **Framework Preset**：选择 **Other**。
   - **Build Command**：填入 `pnpm gen:manifest`。
   - **Output Directory**：保持留空。
4. **配置环境变量**：
   - 展开 **Environment Variables**，根据下方表格逐一添加必要与可选环境变量。
5. **点击部署**：
   - 点击 **Deploy**，Vercel 将在几秒内构建并完成全球 Edge 边缘部署。

---

## 3. Netlify 部署

本项目支持在 Netlify 的 **Edge Functions**（Deno/Web 标准环境）上直接运行，根目录已预配置 [`netlify.toml`](../netlify.toml) 和 [`netlify/edge-functions/server.ts`](../netlify/edge-functions/server.ts)。

### <a id="netlify-部署方法"></a>3.1 部署方法

本项目提供了 **GitHub Actions 自动化一键部署（方案 A，强烈推荐）** 与 **Netlify 控制台手动关联导入（方案 B）** 两种方式。

#### 方案 A（推荐）：GitHub Actions 自动化一键部署（免手动配置面板）

通过本仓库内置的 [`.github/workflows/deploy-netlify.yml`](../.github/workflows/deploy-netlify.yml) 工作流，**所有环境变量均从 GitHub Secrets 自动导入 Netlify 站点**：

1. **获取 Netlify API Token**：
   - 登录 [Netlify Dashboard](https://app.netlify.com/)。
   - 点击左下角头像 -> **User Settings** -> **Applications** -> **Personal access tokens**。
   - 点击 **New access token**，输入名称生成并复制生成的 Token。
2. **在 GitHub 仓库添加 Secret**：
   - 进入你的 GitHub 博客仓库，导航至 **Settings** -> **Secrets and variables** -> **Actions**。
   - 点击 **New repository secret**：
     - **Name**：`NETLIFY_AUTH_TOKEN`（或 `NETLIFY_API_KEY`）。
     - **Value**：粘贴刚刚复制的 Token。
   - *(可选)* 若已有已存在的站点，可添加 `NETLIFY_SITE_ID`（可在 Netlify 站点 Settings -> Site details 复制 API ID）；未填写时脚本会自动按仓库名检索或创建新站点。
3. **手动触发部署**：
   - 进入 GitHub 仓库的 **Actions** 标签页，在左侧选择 **Deploy to Netlify**。
   - 点击右侧 **Run workflow** 按钮即可一键完成全自动构建与发布（不占用 push 触发，按需手动运行）。

---

#### 方案 B：Netlify 控制台手动关联部署

1. **登录 Netlify**：登录 [Netlify Dashboard](https://app.netlify.com/)。
2. **导入 Git 仓库**：
   - 点击 **Add new site** -> **Import an existing project**。
   - 选择 **GitHub** 并授权，选择你的博客代码仓库。
3. **自动识别构建配置**：
   - Netlify 会自动读取仓库根目录的 `netlify.toml`。
   - **Publish directory** 默认识别为 `public`。
   - **Build command** 识别为 `node scripts/gen-manifest.mjs`。
4. **设置环境变量**：
   - 进入 **Site configuration** -> **Environment variables**。
   - 点击 **Add a variable** 逐一添加必要与可选变量。
5. **部署上线**：
   - 点击 **Deploy site**，Netlify 将自动打包并部署 Edge Function，完成后分配 `*.netlify.app` 免费域名。

## 4. 常见问题排查

1. **部署后文章显示 404**：
   - 检查 `GH_OWNER`、`GH_REPO`、`GH_BRANCH` 是否与你的实际 GitHub 仓库一致。
   - 若文章仓库为私有仓库（Private），必须配置具备读取权限的 `GH_TOKEN`。公开仓库无需配置。
2. **没有配置数据库是否报错？**：
   - 完全不会。系统内置 `isStatsEnabled` 检测，未配置 D1 / Supabase 时自动关闭访问量统计与热门文章排行，所有文章展示、TOC 目录、分类标签、评论功能 100% 正常。
3. **自有域名与 HTTPS 证书**：
   - **Cloudflare**：在 `BLOG_URL` 填入你的域名，确保域名已托管在 Cloudflare 上，Action 部署脚本会自动完成 Custom Domain 绑定。
   - **Vercel / Netlify**：直接在各自平台的 **Domain Management** 界面添加你的域名并按提示配置 CNAME 解析即可。
