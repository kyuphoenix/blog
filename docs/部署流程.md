## 1. Cloudflare Workers 部署

Cloudflare Workers 是本博客的**原生主推平台**，具备全球边缘无服务器计算能力、极低延迟与零冷启动优势。本项目提供了一键式 **GitHub Actions 自动化 CI/CD 工作流**，所有敏感凭证保存在 GitHub 仓库中，无需在本地安装复杂环境。

### 1.1 准备凭证

1. 登录 [Cloudflare 控制台](https://dash.cloudflare.com/)。
2. **获取 Account ID**（可选）：
   - 点击左侧菜单 **Workers & Pages** -> **Overview**，在右侧面板复制你的 **Account ID**（未配置时部署脚本亦可自动解析）。
3. **创建 API Token（必须配置部署与清理缓存权限）**：
   - 点击右上角头像 -> **My Profile** -> **API Tokens**。
   - 点击 **Create Token**，选择 **Edit Cloudflare Workers** 模板。
   - 权限确认包含 `Account - Workers KV Storage - Edit`、`Account - Workers Scripts - Edit`、`Account - D1 - Edit` 等。
   - 💡 **一币两用（必须追加 CDN 缓存强刷权限）**：点击 **Add more** 必须追加权限 **`Zone`** -> **`Cache Purge`** -> **`Purge`**（在 Zone Resources 区域选择 `Include` -> `All zones` 或指定域名）。
     > ⚠️ **为什么必须追加**：后续在发布文章或手动执行一键强刷全球 CDN 缓存时，GitHub Actions 工作流将直接读取此 Token 调用 Cloudflare Purge API 清除边缘机房缓存。**若未添加此权限，强刷 CDN 时将报错 403 权限不足**！
   - 创建并复制该 Token。
   > 💡 **全自动免配置特性**：只要你的 API Token 具备上述 KV 和 D1 编辑权限，部署工作流在执行时会**全自动检测、创建并绑定 KV (blog-cache) 与 D1 (blog-db)**，并且自动初始化数据表！**你无需手动到控制台创建 KV / D1，也无需获取任何 ID 填入环境变量**。

### 1.2 执行部署

1. **配置 GitHub Secrets**：
   - 进入你的博客 GitHub 仓库，导航至 **Settings** -> **Secrets and variables** -> **Actions**。
   - 在 **Repository secrets** 中添加 `CLOUDFLARE_API_TOKEN`（填入复制的 Token）。
   - *(可选)* 在 **Repository secrets** 或 **Variables** 中添加 `CLOUDFLARE_ACCOUNT_ID`。
2. **手动触发部署**：
   - 进入 GitHub 仓库的 **Actions** 标签页，在左侧选择 **Deploy to Cloudflare Workers**。
   - 点击右侧 **Run workflow** 下拉按钮：
     - 分支选择 `main`。
     - 运行选项支持在下拉框中选择 `auto`（推荐）、`d1`、`supabase` 或 `none`。
     - 点击绿色 **Run workflow** 按钮启动，约 1~2 分钟即可完成全球发布！

### 1.3 缓存与强制刷新所需环境变量配置

若希望在发布/修改文章时自动清除全球 300+ 机房的 Cloudflare CDN 缓存与 Worker KV 缓存，需在 GitHub 仓库中配置以下变量：

| 变量名称 | 配置位置 | 必填/可选 | 说明与获取方式 |
| :--- | :---: | :---: | :--- |
| `CLOUDFLARE_API_TOKEN` | Secrets | **必填** | 部署凭证直接复用（创建时**必须追加** `Zone - Cache Purge - Purge` 权限） |
| `CLOUDFLARE_ZONE_ID` | Secrets / Variables | 推荐 | 域名 Zone ID。在 Cloudflare 域名控制台概述（Overview）页面右侧面板直接复制，用于发布文章时广播清空全球 CDN |
| `BLOG_URL` | Variables | 推荐 | 博客完整访问地址（如 `https://blog.example.com`）。首次部署成功后填入，用于文章更新时 Webhook 通知 Worker 预热 |
| `PURGE_SECRET` | Secrets | 推荐 | 缓存刷新鉴权密钥（可填写任意随机密码，防恶意刷新） |

> 💡 **提示**：首次部署时只需 `CLOUDFLARE_API_TOKEN` 即可。`CLOUDFLARE_ZONE_ID` 与 `BLOG_URL` 可在部署成功后随时补充，不配置不影响正常部署。

## 2. Vercel 部署

本项目原生支持通过 Vercel **Hono Fluid Compute Preset** 进行极速无服务器渲染（基于 [`src/index.ts`](../src/index.ts) 与 [`vercel.json`](../vercel.json)）。

### 2.1 准备凭证

1. 登录 [Vercel 控制台](https://vercel.com/)。
2. 点击左下角头像 -> 弹出框最上方的设置按钮 -> **Settings** -> **Tokens**。
3. 点击 **Create** 创建一个新 Token（Scope 保持默认），复制生成的密钥。

### 2.2 执行部署

#### 方案 A（推荐）：GitHub Actions 自动化一键部署

本项目内置的 [`.github/workflows/deploy-vercel.yml`](../.github/workflows/deploy-vercel.yml) 工作流支持自动管理项目并同步环境变量，**无需手动到 Vercel 网页控制台逐个添加变量**：

1. 进入博客 GitHub 仓库的 **Settings** -> **Secrets and variables** -> **Actions**。
2. 在 **Repository secrets** 中添加 `VERCEL_TOKEN`（填入刚刚复制的 Token）。
3. 进入 GitHub 仓库的 **Actions** 标签页，选择 **Deploy to Vercel**，点击 **Run workflow** 即可一键完成全自动构建与发布！

#### 方案 B：Vercel 控制台手动导入部署

1. 在 Vercel 控制台点击 **Add New...** -> **Project**，导入你的博客 GitHub 仓库。
2. **构建设置**：
   - **Framework Preset**：选择 **Other**。
   - **Build Command**：填入 `pnpm gen:manifest`。
   - **Output Directory**：保持留空。
3. **配置环境变量**：展开 **Environment Variables**，参考文末总览表格添加必要变量。
4. 点击 **Deploy**，Vercel 将在几秒内构建并完成全球部署。

### 2.3 缓存与强制刷新所需环境变量配置

若希望在发布/修改文章时自动清除 Vercel 全球边缘缓存（Edge Cache），需在 GitHub 仓库中配置以下变量：

| 变量名称 | 配置位置 | 必填/可选 | 说明与获取方式 |
| :--- | :---: | :---: | :--- |
| `VERCEL_TOKEN` | Secrets | **必填** | 部署凭证直接复用，用于调用 Vercel 官方 Edge Cache REST API 刷新缓存 |
| `VERCEL_PROJECT_ID` | Secrets / Variables | 推荐 | 目标项目 ID。可在 Vercel 对应项目 -> **Settings** -> **General** 中复制，用于精确标记清除 |
| `BLOG_URL` | Variables | 推荐 | 部署成功后分配的 `*.vercel.app` 域名或自定义域名，用于文章更新时 Webhook 通知后端清空内存缓存 |
| `PURGE_SECRET` | Secrets | 推荐 | 缓存刷新鉴权密钥（与后端保持一致） |

> 💡 **提示**：本项目采用 Vercel 官方 Edge Cache Invalidation REST API，**无需绑定 Git 仓库，无需创建 Deploy Hook**。首次部署无需提前获取 `VERCEL_PROJECT_ID` 和 `BLOG_URL`，部署成功后再填入即可，未配置时不影响部署发布。

## 3. Netlify 部署

本项目支持在 Netlify 的 **Edge Functions**（Deno/Web 标准环境）上直接运行，根目录已预配置 [`netlify.toml`](../netlify.toml)。

### 3.1 准备凭证

1. 登录 [Netlify Dashboard](https://app.netlify.com/)。
2. 点击左下角头像 -> **User Settings** -> **Applications** -> **Personal access tokens**。
3. 点击 **New access token**，输入名称生成并复制生成的 Token（即 `NETLIFY_API_KEY`）。

### 3.2 执行部署

#### 方案 A（推荐）：GitHub Actions 自动化一键部署

本项目内置的 [`.github/workflows/deploy-netlify.yml`](../.github/workflows/deploy-netlify.yml) 工作流会自动创建或复用站点，并将 GitHub 中的环境变量自动导入 Netlify 生产环境：

1. 进入博客 GitHub 仓库的 **Settings** -> **Secrets and variables** -> **Actions**。
2. 在 **Repository secrets** 中添加 `NETLIFY_AUTH_TOKEN`（或 `NETLIFY_API_KEY`，填入刚刚复制的 Token）。
3. 进入 GitHub 仓库的 **Actions** 标签页，选择 **Deploy to Netlify**，点击 **Run workflow** 即可完成发布。部署脚本会自动按 `${GH_OWNER}-${GH_REPO}` 命名专属站点，并在首次部署后自动将站点 ID 持久化，无需手动干预。

#### 方案 B：Netlify 控制台手动导入部署

1. 在 Netlify 控制台点击 **Add new site** -> **Import an existing project**，授权并选择博客仓库。
2. Netlify 会自动读取仓库根目录的 `netlify.toml`，识别构建命令与静态目录。
3. 进入 **Site configuration** -> **Environment variables**，根据文末总览表格添加环境变量。
4. 点击 **Deploy site**，Netlify 将自动打包并部署 Edge Function，完成后分配 `*.netlify.app` 免费域名。

### 3.3 缓存与强制刷新所需环境变量配置

若希望在发布/修改文章时自动清除 Netlify 全球边缘 CDN 缓存（Purge Cache），需在 GitHub 仓库中配置以下变量：

| 变量名称 | 配置位置 | 必填/可选 | 说明与获取方式 |
| :--- | :---: | :---: | :--- |
| `NETLIFY_AUTH_TOKEN` / `NETLIFY_API_KEY` | Secrets | **必填** | 部署 PAT 凭证直接复用，用于调用 Netlify 官方 Purge API |
| `NETLIFY_SITE_ID` | Secrets / Variables | 推荐 | 目标项目 ID。进入 Netlify 对应项目 -> **Project configuration** -> 复制顶部的 **Project ID**（首次部署脚本也会自动持久化保存） |
| `BLOG_URL` | Variables | 推荐 | 部署成功后分配的 `*.netlify.app` 域名或自定义域名，用于 Webhook 通知清空缓存 |
| `PURGE_SECRET` | Secrets | 推荐 | 缓存刷新鉴权密钥（与后端保持一致） |

> 💡 **提示**：首次部署无需提前获取 `NETLIFY_SITE_ID` 和 `BLOG_URL`，首次部署成功后 Netlify 才会生成对应项目，后续补填即可，未配置时不影响首次部署。

## 4. 常见问题排查与缓存机制

### 1. 缓存驱动机制说明
博客采用统一的 `unstorage` 存储抽象层处理文章与清单缓存，不同平台的底层驱动如下：
- **Cloudflare Workers**：原生接入 Cloudflare Workers KV 绑定（`env.BLOG_CACHE`），享受全球分布式持久化键值缓存。若 API Token 具备权限，部署时将**全自动创建并绑定**。
- **Vercel 与 Netlify**：基于 `unstorage` 高效**内存缓存驱动（Memory Driver）**运行。
  > 💡 **为什么默认使用内存缓存**：Vercel KV 需要额外开通付费 Upstash Redis 数据库，Netlify Blobs 需要引入专用 SDK。本项目经过精心优化设计，采用边缘内存驱动配合 5 分钟 TTL 策略，做到了**零依赖、零额外成本、零配置门槛**。当发布新文章触发自动预热时，配合 `PURGE_SECRET` 即可秒级响应更新。

### 2. 部署后文章显示 404
- 检查 `GH_OWNER`、`GH_REPO`、`GH_BRANCH` 是否与实际 GitHub 仓库一致。
- 若文章仓库为**私有仓库 (Private)**，必须配置具备读取权限的 `GH_TOKEN`。公开仓库留空即可。

### 3. 没有配置数据库是否报错？
- 完全不会。系统内置 `isStatsEnabled` 智能检测，未配置 D1 或 Supabase 时自动以纯净的**零数据库模式**运行，前端不展示阅读计数与热门排行角标，浏览器端完全不发上报请求，核心功能（文章浏览、TOC 目录、分类标签、评论等）100% 正常。

### 4. 绑定自有域名
- **Cloudflare**：在 GitHub Variables 中配置 `BLOG_URL` 为你的自定义域名（确保域名已托管在 Cloudflare 上），部署脚本会自动完成 Custom Domain 绑定。
- **Vercel / Netlify**：直接在各自平台的 **Domain Management** 界面添加你的域名并按提示配置 CNAME 解析即可。

## 5. 环境变量与密钥配置总览

> ⚠️ **关于数据库配置**：
> - 数据库与阅读量统计为**完全可选功能**，相关环境变量（`SUPABASE_URL`、`SUPABASE_KEY`、`DATABASE_URL` 或 `CLOUDFLARE_D1_ID` 等）已统一收敛至独立文档，请查阅：📖 [**`docs/数据库配置.md`**](数据库配置.md)。

### <a id="51-通用基础环境变量-所有平台通用"></a>5.1 通用基础环境变量 (所有平台通用)

配置路径：GitHub 仓库 -> **Settings** -> **Secrets and variables** -> **Actions**

| 变量名称 | 配置位置 | 必填/推荐 | 说明 |
| :--- | :---: | :---: | :--- |
| `BLOG_URL` | Variables | 推荐 | 博客完整访问地址（如 `https://blog.example.com` 或分配的默认域名）。首次部署可留空，部署成功获取域名后再补充填入，用于文章更新时自动 Webhook 刷新缓存 |
| `PURGE_SECRET` | Secrets | **⭐ 强烈推荐** | **缓存刷新保护密钥**。用于接收文章变动触发的 Webhook 刷新缓存请求。可自定义任意随机字符串（如 `my-secret-key-888`），配置后能有效保护缓存刷新接口不被恶意调用 |
| `GH_OWNER` | Variables | 可选 | 存放文章 Markdown 文件的 GitHub 账户用户名（未配置时默认自动读取当前代码仓库拥有者） |
| `GH_REPO` | Variables | 可选 | 存放文章的 GitHub 仓库名（未配置时默认自动读取当前代码仓库名） |
| `GH_BRANCH` | Variables | 可选 | 文章所在分支（未配置时默认读取 `main`） |
| `GH_TOKEN` | Secrets | 条件必填 | **仅当文章仓库为 Private 私有仓库时必须配置**（用于运行时通过 GitHub API 授权拉取文章）；公开仓库留空即可 |
| `GISCUS_REPO` | Variables | 可选 | Giscus 评论绑定的 GitHub 仓库名称（格式如 `username/blog`，需开启 Discussions） |
| `GISCUS_REPO_ID` | Variables | 可选 | Giscus 仓库 ID（从 [giscus.app](https://giscus.app) 获取） |
| `GISCUS_CATEGORY` | Variables | 可选 | Giscus 讨论分区名称（默认为 `Announcements`） |
| `GISCUS_CATEGORY_ID` | Variables | 可选 | Giscus 讨论分区 ID（从 [giscus.app](https://giscus.app) 获取） |

> 💡 **提示**：Giscus 评论系统已内置定制主题，**无需配置任何主题相关变量**。

### <a id="52-平台独立环境变量"></a>5.2 平台独立环境变量

| `CLOUDFLARE_KV_ID` | Secrets / Variables | 备选 | 手动指定的 Cloudflare KV 命名空间 ID（仅当 API Token 权限受限无法自动创建时使用） |
| `CLOUDFLARE_D1_ID` | Secrets / Variables | 备选 | 手动指定的 Cloudflare D1 数据库 ID（仅当 API Token 权限受限无法自动创建时使用） |

#### ▲ 2. Vercel 专属

| 变量名称 | 配置位置 | 必填/可选 | 说明 |
| :--- | :---: | :---: | :--- |
| `VERCEL_TOKEN` | Secrets | **必填** | Vercel API 访问令牌（用于 GitHub Actions 自动部署及调用官方 Edge Cache REST API 刷新缓存） |
| `VERCEL_PROJECT_ID` | Secrets / Variables | 可选 | 目标 Vercel 项目 ID（未配置时默认读取仓库名，配置后可精确指定） |
| `VERCEL_PROJECT_NAME` | Variables | 可选 | 自定义 Vercel 项目名称（默认自动读取当前仓库名） |
| `VERCEL_ORG_ID` | Secrets / Variables | 可选 | Vercel 团队/组织 ID（仅部署至团队空间时需要配置） |

#### 🌐 3. Netlify 专属

| 变量名称 | 配置位置 | 必填/可选 | 说明 |
| :--- | :---: | :---: | :--- |
| `NETLIFY_AUTH_TOKEN` / `NETLIFY_API_KEY` | Secrets | **必填** | Netlify Personal Access Token（用于 GitHub Actions 自动同步变量、构建部署与调用 Purge API） |
| `NETLIFY_SITE_ID` | Secrets / Variables | 可选 | 目标项目 ID（进入 Netlify 对应项目 -> **Project configuration** -> 复制 **Project ID**）。首次部署后脚本会自动保存并持久化写入仓库变量，亦可手动填入 |
| `NETLIFY_SITE_NAME` | Variables | 可选 | 自定义 Netlify 站点名称（默认由 `${GH_OWNER}-${GH_REPO}` 自动拼接唯一专属名称） |

> 📖 **关于全球 CDN 分层缓存架构原理、SWR 与强制缓存失效的详细机制，请查阅**：[**`docs/缓存.md`**](缓存.md)。
