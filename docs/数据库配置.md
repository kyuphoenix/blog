# 方案 A：使用 Supabase (推荐用于跨平台部署，支持 Action 全自动建表)

1. 在 [Supabase](https://supabase.com/) 创建一个新项目。
2. 获取项目凭据：
   - 进入 **Project Settings** -> **Data API**，获取 **API URL**（对应 `SUPABASE_URL`）
   - 进入 **Project Settings** -> **API Keys**，获取 **Publishable key**（对应 `SUPABASE_KEY`）
3. **数据库初始化（支持全自动与手动两种方式）**：
   - **自动初始化（无需手动建表，强烈推荐）**：
     在 GitHub Secrets 中添加 `DATABASE_URL`。
     GitHub Actions 在首次部署时会自动检测数据表是否存在，若未初始化将**自动执行建表、索引、RLS 安全策略与存储过程初始化**！后续部署自动跳过。
   - **手动初始化（备选）**：
     打开 Supabase 项目的 **SQL Editor**，将项目中的 [`db/schema.supabase.sql`](../db/schema.supabase.sql) 内容完整粘贴并点击 **Run** 执行一次即可。

### `DATABASE_URL` 获取方法：
1. 进入 Supabase 对应的数据库项目，点击顶部绿色 **Connect** 按钮。
2. 从上到下依次选择 **Direct** -> **Session pooler** -> **URI**。
3. 复制 `Connection string` 右侧 `postgresql://` 开头的链接。需要用创建数据库时的密码替换 `[YOUR-PASSWORD]` 部分。
4. 密码如果包含某些特殊字符，要先进行 URL 编码。如果忘记密码或者不确定哪些字符需要编码，可以直接点击 **Reset database password** 按钮，输入密码之后会直接把新的密码显示在链接里，可以直接复制。

### 变量配置
| 配置名称 | 凭据类型 | 说明 |
| :--- | :--- | :---: |
| `SUPABASE_URL` | API URL | 必填 |
| `SUPABASE_KEY` | Publishable key | 必填 |
| `DATABASE_URL` | PostgreSQL 直连连接串 | 仅全自动建表需要配置 |

# 方案 B：使用 Cloudflare D1 (专为 Cloudflare Workers 原生设计)

### 1. 全自动初始化（强烈推荐，无需手动建库建表与填 ID）

只要在 GitHub Secrets 中配置的 `CLOUDFLARE_API_TOKEN` 具备 **D1: Edit** 权限（创建 Token 时推荐选择 `Edit Cloudflare Workers` 模板或自定义权限）：
- **全自动创建与绑定**：部署工作流在执行时会**自动检测或创建**名为 `blog-db` 的 D1 数据库，并将其自动绑定至 Worker。
- **全自动建表**：脚本会自动检查数据库是否已就绪，若未建表将**自动执行 [`db/schema.sql`](../db/schema.sql) 创建 `page_views` 与 `post_stats` 表**！
- **完全免配置**：**无需在 Cloudflare 控制台手动操作，更无需获取 Database ID 填入环境变量**，开箱即用。

### 2. 手动初始化（备选，仅当 Token 权限受限时使用）

若你的 `CLOUDFLARE_API_TOKEN` 仅具备 Worker 发布权限而缺少 D1 管理权限，可采用手动配置：
1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com/)，进入 **Workers & Pages** -> **D1**。
2. 点击 **Create database**，创建一个名为 `blog-db` 的数据库，记录页面上显示的 **Database ID**。
3. 进入该数据库控制台的 **Console** 标签页，将项目中的 [`db/schema.sql`](../db/schema.sql) 内容完整粘贴并点击 **Execute** 执行建表。
4. 在 GitHub 仓库 **Settings** -> **Secrets and variables** -> **Actions** 中添加：
   - 变量名称：`CLOUDFLARE_D1_ID`
   - 变量值：填入复制的 Database ID 即可。
