# 统计与数据库配置指南 (Umami / D1 / Supabase)

Honoki 采用了灵活可插拔的**统一统计与数据抽象层**。浏览统计与数据库为**完全可选功能**，提供以下多种模式供你按需选择：

- **⭐ 方案 1：Umami 统计（强烈推荐，免数据库、零配置、无感接入）**
  无需创建或维护任何数据库（免 Cloudflare D1、免 Supabase PostgreSQL），彻底杜绝 Cloudflare D1 权限不足与数据库建表失败问题。自带现代化独立流量大屏，全平台（Cloudflare、Vercel、Netlify）通用！
- **方案 2：Cloudflare D1（专为 Cloudflare Workers 原生设计）**
  基于 Cloudflare 边缘 SQLite 数据库，适合所有服务均深度托管在 Cloudflare 且具备完整 D1 权限的用户。
- **方案 3：Supabase（专为 PostgreSQL 跨平台设计）**
  基于 Supabase 托管 PostgreSQL，适合部署在 Vercel 或 Netlify 且希望拥有自建关系型数据库的用户。
- **方案 4：纯零数据库超轻量模式（默认不配置时）**
  若未配置上述任何服务，博客自动以零数据库极速模式运行，前端不展示阅读计数与热门火焰角标，浏览器端绝不发送任何统计请求，性能极致轻快。

> [!TIP]
> **为什么我们强烈推荐 Umami？**  
> 许多用户在部署 Cloudflare Workers 时，常遇到 `A request to the Cloudflare API (/zones/.../workers/routes) failed: No access to the specified resource` 或 D1 权限受限报错。**接入 Umami 即可完全绕开 D1 权限限制**！GitHub Actions 部署时会自动剥离 D1 绑定，做到 100% 部署成功率，同时还能免费获得一个媲美 Google Analytics 的独立访客分析大屏。

# 方案 1：使用 Umami 统计 (⭐ 强烈推荐)

[Umami](https://umami.is/) 是一款注重隐私、开源且现代化的网站统计分析系统，提供免费的官方云端版（Umami Cloud，个人博客免费额度完全够用），也支持自建私有化实例。

### 1. 获取 Umami 凭据

1. **注册与创建站点**：
   - 打开 [Umami Cloud 官网](https://cloud.umami.is/)（或你的自建 Umami 平台）并登录。
   - 点击 **Websites** -> **Add website**。
   - 填写站点名称（如 `我的博客`）和域名（如 `blog.example.com`），点击 **Save** 保存。
2. **获取 Website ID (必填)**：
   - 在 Websites 列表中，找到刚添加的站点，点击右侧的 **Edit**（编辑）。
   - 复制页面显示的 **Website ID**（一串形如 `8a5c3e41-xxxx-4xxx-xxxx-xxxxxxxxxxxx` 的 UUID）。
3. **获取 API Key (强烈建议配置)**：
   - 后端拉取文章浏览量（Pageviews）以及计算首页 Top 3 热门置顶需要 API 鉴权。
   - 在 Umami 平台点击右上角头像 / **Settings** -> **API Keys** -> **Create API Key**。
   - 输入名称（如 `Honoki Blog API`），点击确认生成。
   - **立即复制生成的 API Key**（注意：出于安全考虑，该密钥仅显示一次）。

### 2. 配置 GitHub 环境变量

进入 GitHub 博客仓库 -> **Settings** -> **Secrets and variables** -> **Actions**：

| 变量名称 | 配置位置 | 必填/可选 | 说明 |
| :--- | :---: | :---: | :--- |
| `UMAMI_WEBSITE_ID` | Variables / Secrets | **必填** | 你的 Umami 站点 UUID。**只要配置此项，系统自动优先选用 Umami 统计引擎**，部署时自动剥离 D1 数据库绑定。 |
| `UMAMI_API_KEY` | Secrets | **建议配置** | 用于服务端安全拉取文章阅读数及首页 Top 3 热门文章排行。 |
| `UMAMI_HOST` | Variables | 可选 | 若使用官方 Umami Cloud，默认即为 `https://cloud.umami.is`，**留空即可**；若为自建实例，填入自建完整域名（如 `https://analytics.example.com`，末尾不带斜杠）。 |
| `ENABLE_UMAMI_SCRIPT` | Variables | 可选 | 默认为 `true`（博客 HTML `<head>` 中自动注入官方 `script.js` 追踪脚本）；若设为 `false` 则完全通过博客后端代理上报。 |

> [!NOTE]
> **双重防刷与无感知上报机制**：  
> - 正常访问时，官方 `script.js` 脚本负责静默追踪；
> - 若访客浏览器安装了 Adblock 等去广告插件拦截了上报脚本，Honoki 后端服务会自动激活**无感知服务端代理上报**（Server-side Proxy），确保每篇阅读量不丢失；同时后端已内置 60 秒边缘缓存，绝不给上游 Umami 服务带来高频请求负担。

# 方案 2：使用 Cloudflare D1 (专为 Cloudflare Workers 原生设计)

如果你希望将阅读数据完全存放在 Cloudflare 原生的 SQLite 边缘数据库中，可以使用 Cloudflare D1。

### 1. 全自动初始化（无需手动建库建表与填 ID）

只要在 GitHub Secrets 中配置的 `CLOUDFLARE_API_TOKEN` 具备 **D1: Edit** 权限（创建 Token 时推荐选择 `Edit Cloudflare Workers` 模板或自定义权限）：
- **全自动创建与绑定**：部署工作流在执行时会**自动检测或创建**名为 `honoki_db` 的 D1 数据库，并将其自动绑定至 Worker。
- **全自动建表**：脚本会自动检查数据库是否已就绪，若未建表将**自动执行 [`db/schema.sql`](../db/schema.sql) 创建 `page_views` 与 `post_stats` 表**！
- **完全免配置**：**无需在 Cloudflare 控制台手动操作，更无需获取 Database ID 填入环境变量**，开箱即用。

### 2. 手动初始化（备选，仅当 Token 权限受限时使用）

若你的 `CLOUDFLARE_API_TOKEN` 仅具备 Worker 发布权限而缺少 D1 管理权限，可采用手动配置：
1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com/)，进入 **Workers & Pages** -> **D1**。
2. 点击 **Create database**，创建一个名为 `honoki_db` 的数据库，记录页面上显示的 **Database ID**。
3. 进入该数据库控制台的 **Console** 标签页，将项目中的 [`db/schema.sql`](../db/schema.sql) 内容完整粘贴并点击 **Execute** 执行建表。
4. 在 GitHub 仓库 **Settings** -> **Secrets and variables** -> **Actions** 中添加：
   - 变量名称：`CLOUDFLARE_D1_ID`
   - 变量值：填入复制的 Database ID 即可。

# 方案 3：使用 Supabase (专为 PostgreSQL 跨平台设计)

适合将博客部署在 Vercel 或 Netlify，且希望拥有外部 PostgreSQL 关系型数据库的用户。

### 1. 获取 Supabase 凭据

1. 在 [Supabase](https://supabase.com/) 创建一个新项目。
2. 获取项目凭据：
   - 进入 **Project Settings** -> **Data API**，获取 **API URL**（对应 `SUPABASE_URL`）
   - 进入 **Project Settings** -> **API Keys**，获取 **Publishable key**（对应 `SUPABASE_KEY`）

### 2. 数据库初始化（支持全自动与手动两种方式）

- **自动初始化（无需手动建表，推荐）**：
  在 GitHub Secrets 中添加 `DATABASE_URL`。
  GitHub Actions 在首次部署时会自动检测数据表是否存在，若未初始化将**自动执行建表、索引、RLS 安全策略与存储过程初始化**！后续部署自动跳过。
- **手动初始化（备选）**：
  打开 Supabase 项目的 **SQL Editor**，将项目中的 [`db/schema.supabase.sql`](../db/schema.supabase.sql) 内容完整粘贴并点击 **Run** 执行一次即可。

#### `DATABASE_URL` 获取方法：
1. 进入 Supabase 对应的数据库项目，点击顶部绿色 **Connect** 按钮。
2. 从上到下依次选择 **Direct** -> **Session pooler** -> **URI**。
3. 复制 `Connection string` 右侧 `postgresql://` 开头的链接。需要用创建数据库时的密码替换 `[YOUR-PASSWORD]` 部分。
4. 密码如果包含某些特殊字符，要先进行 URL 编码。若忘记密码可点击 **Reset database password** 重新生成。

### 变量配置

| 配置名称 | 凭据类型 | 说明 |
| :--- | :--- | :---: |
| `SUPABASE_URL` | API URL | 必填 |
| `SUPABASE_KEY` | Publishable key | 必填 |
| `DATABASE_URL` | PostgreSQL 直连连接串 | 仅全自动建表需要配置 |

## 引擎优先级与手动切换说明

博客内置了自动识别与优先级判定机制：

1. **自动判定 (默认 `auto`)**：
   - 若检测到 `UMAMI_WEBSITE_ID`：优先使用 **Umami 统计**（自动剥离 D1 绑定，免数据库）。
   - 若未配置 Umami 且配置了 `SUPABASE_URL`：使用 **Supabase**。
   - 若仅有 Cloudflare D1 绑定：使用 **Cloudflare D1**。
   - 若均未配置：进入**零数据库超轻量模式**。
2. **显式指定**：
   - 你可以通过在 GitHub Variables 中配置 `DATABASE_TYPE`（可选值：`umami` / `d1` / `supabase` / `none`）来强行指定所用引擎。
   - 在 GitHub Actions 手动执行 **Deploy to Cloudflare Workers** 工作流时，也可在下拉菜单中直接选择对应引擎一键切换。
3. **运行状态查看**：
   - 访问线上博客的 `/api/stats/status` 端点（例如 `https://yourblog.com/api/stats/status`），可实时查看当前实例正连接的引擎类型（`umami`、`d1`、`supabase` 或 `none`）。
